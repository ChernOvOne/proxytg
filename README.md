# MTProxy Manager (tgp)

Полноценный менеджер Telegram MTProxy серверов с CLI интерфейсом.  
Установка одной командой, управление через меню, поддержка 3-х реализаций прокси.

## Быстрая установка

```bash
bash <(curl -sL https://raw.githubusercontent.com/ChernOvOne/proxytg/main/install.sh)
```

После установки управление:

```bash
tgp
```

## Подготовка сервера

### 1. VPS сервер

Вам нужен VPS сервер **за пределами России** (Нидерланды, Германия, Финляндия и т.д.).
Минимальные требования:
- **1 vCPU, 512 MB RAM** — достаточно для сотен пользователей
- **Ubuntu 22.04/24.04** рекомендуется (поддерживаются также Debian, CentOS, Fedora)

### 2. Домен (рекомендуется)

Для ссылок вида `https://t.me/proxy?server=proxy.example.com&port=443&secret=...` нужен домен.
Без домена ссылки будут с IP-адресом — они легче блокируются.

**Настройка домена:**

1. Купите домен или используйте существующий
2. Зайдите в DNS-панель вашего домена (Cloudflare, Namecheap, и т.д.)
3. Создайте **A-запись**:

```
Тип:   A
Имя:   proxy          (или любое другое, например tg, mtproxy)
IP:    IP_ВАШЕГО_VPS
TTL:   Auto
Proxy: OFF ❌          (если Cloudflare — обязательно отключить оранжевое облако!)
```

4. Проверьте что домен резолвится:
```bash
dig proxy.example.com +short
# Должен вернуть IP вашего VPS
```

5. После установки менеджера укажите домен: `tgp` → пункт 8 → введите домен

> **Важно:** Если используете Cloudflare — **отключите проксирование** (оранжевое облако) для этой записи.
> MTProxy — это не HTTP, Cloudflare не может проксировать этот трафик.

### 3. SNI домен для маскировки

Это **другой** домен — не ваш. Это сайт, под который маскируется трафик прокси.
DPI (система блокировок) видит что вы подключаетесь к `max.ru`, а не к Telegram.

- Рекомендуются **короткие** российские домены: `max.ru`, `ya.ru`, `vk.com`, `ok.ru`
- Длинные домены (например `www.google.com`) **обрезаются** на некоторых провайдерах — не используйте!
- Настраивается при установке прокси или через `tgp` → пункт 12

## Что это такое

MTProxy — специальный прокси-протокол от Telegram для обхода блокировок. Трафик маскируется под обычный HTTPS, что делает его невидимым для систем DPI (Deep Packet Inspection).

Этот менеджер позволяет установить и управлять тремя реализациями MTProxy на одном сервере:

| Реализация | Язык | Fake TLS | Описание |
|-----------|------|----------|----------|
| **telemt** | Rust | Да (TLS-Fronting) | Самая продвинутая маскировка, мульти-юзер, API статистика |
| **mtg** | Go | Да (ee-секрет) | Простой и надежный, Prometheus метрики |
| **MTProxy Official** | C | Нет (dd-секрет) | Оригинал от Telegram, без маскировки |

## Возможности

### 📦 Установка и управление
- Установка всех 3-х прокси одной командой или по отдельности
- Запуск / остановка / перезапуск каждого сервиса
- Переустановка и полное удаление
- Проверка наличия сервисов при повторной установке

### 🎭 Маскировка трафика (SNI)
- Настройка SNI домена — DPI видит HTTPS к обычному сайту (например `max.ru`)
- Смена SNI домена через меню без переустановки
- Автоматическая перегенерация секрета при смене домена
- Рекомендуются короткие домены (`max.ru`, `ya.ru`, `vk.com`)

### 🌍 Домен в ссылках
- Домен вместо IP в ссылках для подключения
- Проверка DNS при настройке домена
- Формат: `https://t.me/proxy?server=ДОМЕН&port=ПОРТ&secret=СЕКРЕТ`

### 👥 Мульти-юзер (telemt)
- Несколько пользователей на одном сервере — каждый со своей ссылкой
- Отдельная статистика: подключения, уникальные IP, трафик
- Per-user Ad Tag — разные рекламные теги для разных каналов
- Добавление/удаление через меню

### 📢 Рекламные теги
- Поддержка Ad Tag от @MTProxybot (telemt, MTProxy Official)
- Смена тега через меню

### 📊 Мониторинг
- Статистика подключений в реальном времени (telemt API)
- Уникальные IP = реальные пользователи (не соединения)
- Просмотр логов (последние записи и live-режим)
- Информация о сервере (CPU, RAM, Disk, порты)
- Prometheus метрики (mtg)

### 🔄 Обновления
- Проверка обновлений каждого прокси-сервиса
- Обновление прокси из GitHub releases
- Self-update менеджера (tgp)

### 🛡 Система
- **Firewall** — автоматическое открытие портов (ufw/firewalld/iptables)
- **TCP BBR** — включение ускорения сети одной кнопкой
- **Backup/Restore** — сохранение и восстановление конфигурации

## Порты по умолчанию

| Сервис | Порт | Протокол |
|--------|------|----------|
| telemt | 443 | Fake TLS (выглядит как HTTPS) |
| mtg | 8443 | Fake TLS |
| MTProxy Official | 8888 | MTProto (без маскировки) |

> telemt на порту 443 — лучшая маскировка, т.к. HTTPS обычно работает на 443.

## Требования

- **ОС**: Ubuntu 20.04+ / Debian 10+ / CentOS 7+ / Fedora / Rocky / Alma
- **Права**: root
- **Домен**: рекомендуется (но не обязателен)
- **Зависимости**: curl, git, jq, openssl, bc (устанавливаются автоматически)
- **Для Official MTProxy**: build-essential, libssl-dev, zlib1g-dev (устанавливаются при выборе)

## Требования к клиенту Telegram

Для работы Fake TLS прокси (telemt, mtg) клиент **обязательно** должен быть обновлён:

| Платформа | Минимальная версия | Статус |
|-----------|-------------------|--------|
| Desktop | 6.7.2+ | ✅ Исправлен TLS ClientHello |
| Android | 12.6.4+ | ✅ Исправлен TLS ClientHello |
| iOS | ожидается | ⏳ |

> С 1 апреля 2026 ТСПУ (DPI) блокирует MTProxy по JA3/JA4 fingerprint TLS ClientHello.
> Без обновлённого клиента Fake TLS прокси **не работают** из России.

## Мульти-юзер

telemt поддерживает несколько пользователей на одном сервере. Каждый пользователь получает:

- Свою ссылку (отдельный секрет)
- Свою статистику (подключения, уникальные IP, трафик)
- Свой Ad Tag (можно рекламировать разные каналы)

Пример использования:
```
tgp → 13 → Добавить пользователя → "channel_crypto"
tgp → 13 → Добавить пользователя → "friends"
tgp → 13 → Список пользователей
```

Результат:
```
📌 channel_crypto
   Подключений: 12 | IP: 8 | Трафик: 234.5 MB
   🔗 https://t.me/proxy?server=proxy.example.com&port=443&secret=ee...

📌 friends
   Подключений: 3 | IP: 2 | Трафик: 45.2 MB
   🔗 https://t.me/proxy?server=proxy.example.com&port=443&secret=ee...
```

```

  common.sh         — общие функции, конфиг, цвета
  telemt.sh         — модуль telemt (Rust)
  mtg.sh            — модуль mtg (Go)
  mtproxy.sh        — модуль Official MTProxy (C)
  domain.sh         — управление доменом, портами, SNI
  adtag.sh          — управление рекламными тегами

  updater.sh        — обновления сервисов и self-update

```

## Конфигурация

Файлы конфигурации:
- Менеджер: `/etc/mtproxy-manager/config`
- telemt: `/etc/mtproxy-manager/telemt/config.toml`
- mtg: `/etc/mtproxy-manager/mtg/config.toml`
- Бэкапы: `/root/mtproxy-backup/`

## Удаление

Полное удаление через меню: `tgp` → 7 → "Полное удаление"

Или вручную:
```bash
systemctl stop telemt mtg mtproxy
systemctl disable telemt mtg mtproxy
rm -f /etc/systemd/system/{telemt,mtg,mtproxy}.service
rm -f /usr/local/bin/{telemt,mtg,mtproto-proxy,tgp}
rm -rf /etc/mtproxy-manager /opt/mtproxy-manager /opt/MTProxy
systemctl daemon-reload
```
